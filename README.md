# ML-Assisted Programming of 1T1R Hybrid Synaptic Cells

A college term project combining VTEAM memristor modeling, Python-controlled ngspice simulations, regression models, an interactive design interface, and fresh simulation-based verification.

## Objective

Explore how NMOS width, bitline voltage, and programming-pulse duration influence a 1T1R cell's final resistance and device energy. Use simulation data to suggest candidate settings for requested resistance and energy targets, then verify those settings in ngspice.

The project uses an established 1T1R architecture; it does not claim a new cell, a global optimum, or fabricated-device validation.

## Workflow

```text
Device and circuit setup → Initial verification → Automated simulations
        → Dataset analysis → Model training → Interactive search
        → Fresh ngspice verification
```

## Dependencies

- Python, NumPy, pandas, SciPy, Matplotlib, scikit-learn, and joblib.
- Tkinter for the interface.
- ngspice and a compatible `ptm45.pm` transistor model.
- Cadence Virtuoso/Verilog-A for separate schematic checks.
- OpenVAF/OSDI artifacts are part of the model-development folders; the supplied dataset-generation and verification scripts implement VTEAM behavior directly in the netlist and do not require compiling Verilog-A for those runs.

Install Python packages:

```bash
python -m pip install numpy pandas scipy matplotlib scikit-learn joblib
```

Install ngspice and make its executable available on `PATH`. Tkinter may require separate installation depending on the Python environment. The verification script specifically looks for `ngspice.exe`; adapt that lookup for other platforms.

Check that the PTM file defines the NMOS model expected by the scripts (`nmos` by default). External model files and executables remain subject to their original distribution terms.

## Running the workflow

Commands below assume the terminal starts in `term/`.

### 1. Generate data

```bash
cd script
python run_simulation_loop.py
cd ..
```

The script attempts 1,000 simulations and writes `script/1t1r_dataset.csv` and its metadata. It includes a preliminary time-step comparison and excludes failed cases. Confirm the successful-run count. Re-running overwrites the generated CSV and metadata.

### 2. Keep dataset copies synchronized

The scripts read a CSV beside their own file; they do not automatically share one central dataset. After regeneration, copy the new CSV to the analysis and training folders.

Windows PowerShell:

```powershell
Copy-Item script/1t1r_dataset.csv ML_model/1t1r_dataset.csv
Copy-Item script/1t1r_dataset.csv ML_model_2/1t1r_dataset.csv
```

macOS/Linux shell:

```bash
cp script/1t1r_dataset.csv ML_model/1t1r_dataset.csv
cp script/1t1r_dataset.csv ML_model_2/1t1r_dataset.csv
```

Retrain after changing the dataset. The interface's saved models and support-data CSV must come from the same training run.

### 3. Train the forward models

```bash
cd ML_model_2
python train_forward_width.py
cd ..
```

Outputs in `ML_model_2/forward_outputs/` include:

- `forward_results.csv`
- `forward_metadata.json`
- `permutation_importance.csv`
- `pred_vs_actual_2input.png`
- `pred_vs_actual_3input.png`
- `width_permutation_importance.png`
- `forward_models_3input.joblib`

Only load trusted joblib files. Saved deployment Gaussian-process models are refitted on all samples after held-out evaluation.

### 4. Generate the combined report figure

```bash
cd ML_model
python extra_plots.py
cd ..
```

This creates `report_figures.png`, `report_figures.pdf`, and supporting CSV files in `ML_model/`. Panels (e)–(f) show a two-input joint MLP, not the selected three-input Gaussian-process deployment models.

### 5. Launch the prediction interface

```bash
cd ML_model_2
python forward_design_panel.py
cd ..
```

Enter desired resistance in kΩ, desired device energy in pJ, and the allowed resistance and energy deviations. Energy is a desired value, not an upper budget.

The interface searches width, bitline amplitude, and duration using saved forward models. It displays predicted responses and screening status, saving records in:

- `ML_model_2/forward_outputs/latest_forward_design.csv`
- `ML_model_2/forward_outputs/forward_design_history.csv`

Initial state, gate voltage, and transistor length remain fixed. The interface does not retrain models for each request.

### 6. Verify candidates

Copy the chosen settings into `CANDIDATES` in `verification/run_verification.py`:

```python
# label, width_nm, voltage_V, duration_us, target_R_kohm, target_E_pj
("example", 693.884, 1.560298, 347.047853, 145, 7000)
```

Then run:

```bash
cd verification
python run_verification.py
cd ..
```

The script does not automatically read the interface CSV. It writes fresh `.cir`, `.log`, and `.raw` files for the listed candidates. Existing log and waveform files with the same labels are removed before each run.

## Dataset configuration

| Parameter | Setting |
|---|---|
| NMOS width | 200–1200 nm |
| NMOS length | 45 nm |
| Bitline amplitude | 0.8–2.0 V |
| Wordline voltage | 1.5 V |
| Initial state | 1.5 nm |
| Initial resistance | 100.05 kΩ |
| State range | 0–3 nm |
| Target state increase | 0.02–1.4 nm, log-uniform |
| Configured duration limits | 1 µs–10 ms |
| Sampling seed | 12345 |

Width and voltage are uniformly sampled. Pulse duration is estimated using a sampled target state change and the positive VTEAM rate, then clamped to the limits. Duration is not independently uniform. The estimate neglects transistor drop and pulse edges; the final response comes from ngspice.

The behavioral implementation represents state using a capacitor-node voltage numerically scaled as 1 V = 1 nm. This is not the physical memristor voltage. The dataset covers positive-pulse, resistance-increasing programming from a fixed initial state.

### CSV columns

```text
sample_id, w_mos_nm, v_bl, t_pw_us,
w_init_nm, w_final_nm, delta_w_nm,
r_init_kohm, r_final_kohm,
e_device_pj, e_supply_pj, i_max_ua
```

`e_device_pj` represents memristor energy. `e_supply_pj` represents energy delivered by the bitline source to the branch. Neither includes complete gate-driver and peripheral energy.

## Machine-learning evaluation

Models compared: linear regression, 300-tree random forest, joint MLP with two 64-neuron hidden layers, and Gaussian-process regression.

- Two-input features: voltage and log10 duration.
- Three-input features: width, voltage, and log10 duration.
- Targets: final resistance and log10 device energy.
- Split: 800 training / 200 test samples, seed 42.

| Model | Resistance MAE (kΩ) | Device-energy MAE (pJ) |
|---|---:|---:|
| Two-input joint MLP | 0.9113 | 56.196 |
| Two-input Gaussian process | 0.0890 | 9.574 |
| Three-input Gaussian process | 0.0031 | 0.312 |

Energy errors are measured after transforming predictions back to pJ. Scores refer to the held-out evaluation fits, not independent tests of the deployment models refitted on all data. Model selection used this comparison.

| Quantity | Point 1 | Point 2 |
|---|---:|---:|
| Target resistance (kΩ) | 145 | 158 |
| Simulated resistance (kΩ) | 145.151 | 158.150 |
| Absolute resistance deviation (kΩ) | 0.151496 | 0.149605 |
| Desired device energy (pJ) | 7000 | 7500 |
| Simulated device energy (pJ) | 6981.96 | 7471.15 |
| Absolute energy deviation (%) | 0.2577 | 0.3847 |
| Status | PASS | PASS |

Acceptance tolerances are ±1 kΩ and ±2% device energy. Log errors use unrounded responses. These are target-versus-achieved deviations, not surrogate-versus-SPICE errors.

## Limitations

- Simulation-based work, not fabricated-device validation.
- Virtuoso uses a GPDK045 setup; automated ngspice simulations use PTM. Numerical equivalence is not assumed.
- The Verilog-A and behavioral implementations differ in state representation and numerical update mechanisms.
- High accuracy applies to the sampled deterministic model and fixed initial state, not arbitrary devices or operating conditions.
- Data-support checks are heuristics, not feasibility or safety guarantees.
- Width has low measured importance in this dataset; returned widths are neither unique nor minimum-area designs.
- Only two final candidate points are verified. No design-wide yield, global-optimality, or measured runtime-speedup claim is made.
- Voltage and duration are coupled by sampling; permutation importance is not independent physical sensitivity.
